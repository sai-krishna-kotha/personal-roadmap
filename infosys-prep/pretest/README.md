> Goal: prepare systematically for the Infosys Specialist Programmer L1 training pre-test, build confidence in the listed technology areas, and free up time to focus on an AI project after the assessment.
>

## Roadmap at a glance

| Phase | Weeks | Outcome |
|---|---:|---|
| Build foundations | 1–3 | Reliable Python code tracing; daily Linux and Git practice |
| Learn tooling deeply | 4–6 | Shell, permissions, Git workflows, debugging and recovery |
| Frontend fundamentals | 7–9 | Understand React core; learn Angular fundamentals sufficiently to compare |
| Exam practice | 10–11 | Mixed, timed MCQs and error-log revision |
| Final consolidation | 12 | Two or more full mocks, close knowledge gaps, light revision |

Treat the 12 weeks as a flexible plan, not a deadline. You said you have time, so understand the concepts properly rather than memorizing lists. Repeat any phase until you meet its checkpoint.

## Study method

For each concept:

1. **Understand** the explanation and write a one-line summary in your own words.
2. **Predict** code output or command behavior before running it.
3. **Practice** with at least 5–10 MCQs or small tasks.
4. **Explain** why every incorrect option is wrong.
5. **Review** after 1 day, 3 days, 7 days, and 14 days.
6. **Log errors** with the concept, why you missed it, the correct rule, and a fresh example.

Use a notebook or spreadsheet with these columns: Date, Subject, Topic, Questions attempted, Correct, Accuracy, Mistake type, Revisit date.

### Suggested daily routine

- 60–90 minutes: primary subject of the day.
- 30–45 minutes: hands-on terminal/coding practice.
- 20–30 minutes: MCQs and error log.
- 10 minutes: spaced review of older topics.

Use one lighter day per week for review and a mixed quiz. If you have more time, extend the practice rather than simply increasing the number of topics.

## 12-week plan

### Weeks 1–3 — Python core

- Week 1: types, expressions, control flow, strings, lists, tuples, sets and dictionaries.
- Week 2: mutability, identity/equality, references, slicing, comprehensions, functions, scope and argument passing.
- Week 3: OOP, exceptions, imports, iterators/generators, decorators basics, file handling, standard library and code tracing.

**Checkpoint:** score at least 85% on two different Python topic quizzes, explain every miss, and correctly trace at least 20 unseen snippets without executing them.

### Weeks 4–6 — Linux and Git

- Week 4: filesystem navigation, file operations, paths, `cat`, `less`, `head`, `tail`, `grep`, `find`, globbing and quoting.
- Week 5: permissions, ownership, processes, environment variables, exit status, pipes, redirection, archives and basic shell scripts.
- Week 6: repository states, staging, commits, branches, remote tracking, fetch/pull/push, merge conflicts, reset/revert/reflog and `.gitignore`.

**Checkpoint:** perform common Linux tasks from memory and recover a deliberately created Git mistake in a throwaway repository without losing committed work.

### Weeks 7–9 — Frontend fundamentals

- Week 7: JavaScript essentials needed for frontend questions: scope, closures, arrays/objects, destructuring, modules, promises and async/await.
- Week 8: React components, JSX, props, state, events, rendering, keys, forms, hooks and effects.
- Week 9: Angular components, templates, interpolation, property/event/two-way binding, directives, pipes, services, dependency injection, lifecycle and introductory RxJS. Compare React and Angular concepts.

**Checkpoint:** explain the purpose and behavior of each listed concept, trace small examples, and score at least 80% on separate React and Angular quizzes. If official material identifies only one framework, shift extra time to that framework.

### Weeks 10–11 — Integrated MCQ preparation

- Complete at least 3 topic-specific quizzes per week.
- Complete 2 mixed quizzes each week, interleaving Python, Linux, Git, JavaScript and frontend concepts.
- Make some questions timed, but prioritize accuracy first.
- Revisit every error after 24 hours and again after several days.
- Practice output prediction, command selection, scenario questions and “which statement is true?” questions.

**Checkpoint:** consistently achieve 85% or higher on fresh mixed questions, without relying on memorized answers.

### Week 12 — Final consolidation

- Take two full-length mock tests under realistic conditions. Until official duration and question count are known, choose a consistent time limit and record it; do not mistake it for the real exam format.
- Analyse mistakes by topic and reason.
- Revise only the error log, command sheet, language gotchas and framework comparison table.
- Keep the final day light: flashcards, short quizzes and adequate sleep.

**Ready rule:** aim for 85–90% on at least three fresh mixed mock tests, with no subject consistently below 80%. These are personal readiness targets, not Infosys cutoffs.

## Weekly checkpoints

At the end of each week, answer these without notes:

- Can I explain the topic simply?
- Can I predict the output/result before execution?
- Can I distinguish closely related terms or commands?
- Can I solve a new example, not just one I have seen?
- Have I reviewed old errors and tracked my score?

If two or more answers are “no,” schedule another revision block before progressing.

## Mock-test strategy

1. Read the question stem and identify the exact task: output, concept, command, or scenario.
2. Eliminate options that violate a clear rule.
3. For code, track each variable/reference and each mutation carefully.
4. For Linux/Git, ask what state the command reads and what state it changes.
5. For UI frameworks, distinguish data flow, rendering, lifecycle, and side effects.
6. Mark uncertain questions and return to them instead of spending too long on one item.
7. After the mock, record why each error happened: knowledge gap, misread, rushed reasoning, or guess.

Do not infer the exam’s marking scheme or attempt strategy until official instructions confirm negative marking, skipping behavior, and timing.

## After the pre-test: AI project plan

The objective is not only to clear the pre-test; it is to create enough technical fluency to make a useful AI project.

### Project idea: AI Learning Companion

Build an application that turns notes or permitted learning material into:
- topic summaries and concept cards;
- MCQs with explanations;
- spaced-repetition review scheduling;
- an error dashboard showing weak concepts;
- optional retrieval-augmented question answering with citations to the uploaded material.

### Suggested stack

- Frontend: React
- Backend: FastAPI or Django REST Framework
- Database: PostgreSQL
- AI: a hosted LLM API or a locally runnable model; keep the model provider behind a small interface
- Retrieval: start with keyword search, then add embeddings/vector search if it adds measurable value
- Quality: unit tests, prompt/evaluation set, logging, deployment and a clear README

### Four-week build outline after the pre-test

1. Week 1: define user stories, data model, API contract and a working manual quiz flow.
2. Week 2: add topic generation and MCQ explanations, with guardrails for unsupported answers.
3. Week 3: add spaced repetition, progress tracking and retrieval grounded in user-provided content.
4. Week 4: evaluation, testing, deployment, screenshots, architecture diagram and project write-up.

Keep the AI project as a separate goal. During pre-test preparation, spend only one small weekly session exploring project ideas so it does not compete with exam readiness.
